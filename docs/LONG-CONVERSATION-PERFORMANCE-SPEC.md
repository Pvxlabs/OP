# OP 长对话性能专项 SPEC

日期：2026-10-21（Asia/Shanghai）。状态：M0、M1 基线、M1-L 加载链路与测量工具验收 PASS；
未证实可修复的 OP 主要瓶颈，M2 归因门禁未通过；M3 无优化候选可复测。

## 目标与实施契约

对用户指定的“续接Strategy Host重构”建立真实运行基线，区分官方会话
读取、网页渲染和 OP 附加观察开销；只针对测得的 OP 瓶颈作最小优化。
性能收益与功能正确性分别验收，不能用模拟数据或构建通过替代真实会话结果。

## 边界

- 保留入口的七个 dirty 文件及其全部修改；先保存 patch、SHA256 和安装包清单。
- 不删、移除、重排或隐藏官方消息节点，不改变网页 CSS、React 状态或会话分支。
- 不清缓存、不删除网站存储、不退出登录、不读取或迁移 Cookie/Token/认证信息。
- 不发送消息、不点击查询/派发按钮；只读该会话、滚动、正常导航。输入性能若需
  测量，只使用确认空白的编辑器和随后移除的合成草稿，绝不提交。
- 保留消息/会话身份、完整性、错误/停止/中断、稳定时间和回复保护规则；
  不以采集更少的历史或漏掉保护状态作为性能优化。
- 诊断使用现有 CEF 进程内 DevTools 与隔离 world，不开放调试端口，不调用私有
  ChatGPT API。只存计数、耗时、状态和数值，不存网页正文、完整 URL 或会话 ID。
- 真实测量保持原 bundle/profile/team identity。允许在正常退出、已验证回滚包和
  一致 SQLite 备份后安装已签名的测量/优化包；不并行运行同 profile，不复制认证资料。
- 合成回归使用独立 bundle/profile/mock keychain，不触碰工作会话或真实 CLINX 执行。
- 不升级 CEF，不重写聊天界面，不做自动摘要/新会话迁移；实现阶段不自动提交或推送。
  2026-10-21 用户随后明确授权提交和推送当前对话工作，仅包含本专项改动，
  入口已有的七个文件修改继续保留在工作区，不纳入本次提交。

## 阶段和推进门禁

### M0 — 冻结边界（PASS）

保存 dirty patch/哈希、已安装包哈希、SQLite 一致备份与消息指纹；建立本 SPEC。

### M1 — 测量与根因定位（基线 PASS；OP 主因归因 BLOCKED）

1. 加入不改变采集调度/语义的、手动开启的有界数值测量。
2. 记录环境、目标匹配、已渲染消息/节点数量、viewport、后台/加载状态；
   主进程/renderer CPU 和 RSS；frame interval、event-loop delay、long-task。
3. 分别记录 OP collector、mutation handler、completion observer 的调用次数、
   累积/最大同步耗时、正文缓存 miss、扫描节点量与发送批次。
4. 同一窗口/缩放/滚动流程采集至少 3 轮，每轮约 30 秒（空闲与滚动分开）。
   不把 rAF 间隔称为物理显示延迟；API 不可用、HTTP 故障或正文缺失明确 BLOCKED。
5. 以耗时占比和工作量定位；归因不足时不做猜测性网页优化。必要时用有界 profiler
   对照，但不输出带私密内容的脚本源码/URL。先完成本阶段结论再推进 M2。
6. 本阶段测量代码必须完成隐私、隔离、保护记录和现有 CEF 回归；这是 M1
   的工具正确性验收，不代表已推进 M2 或 M3 的优化验收。

### M1-L — 打开/刷新加载链路（PASS，用户明确最明显症状）

用户补充：打开或刷新时长时间转圈。优先在原窗口进行至少三次普通刷新，
分别记录刷新起点、主文档请求响应头/结束及加载结束、会话 GET 响应头/结束、首个非空回复批次
进入本地桥接与接受确认；UI 正文可见只记为截图观察上界，不冒充精确首屏。
新增手动测量入口，跨文档导航生效，60 秒自动结束，事件上限 128；
默认关闭，不增加请求/重试，不保存 URL、身份或正文。请求耗时包含客户端排队、
网络与服务端，不能称为纯服务端计算时间。刷新样本不代表冷启动/所有打开路径。
新文档隔离 context 就绪后自动启动既有 30 秒数值探针，单独保存文档内起点、
OP 三条观察路径耗时及 renderer 指标；报告其覆盖起点，不能覆盖更早的工作。

此子阶段只补充诊断；若主耗时落在官方请求等待，M2 不做猜测性缓存或 DOM 改写。
若存在显著 OP 本地等待，先证明具体路径，再按 M2 实施和同条件验收。

验收结果：三次普通刷新主文档 HTTP 200，响应头到达 0.45–0.74 秒，接收结束
2.40–3.55 秒，首批回复进入观察器 2.94–4.23 秒；本地接受 1.7–3.2 毫秒。
三条 OP 观察路径在各自 30 秒采样中累计 13.8–22.2 毫秒，文档内采样起点
0.55–0.85 秒；不覆盖更早工作，也不代表所有 OP/CEF 开销。
本次没有复现此前约 24 秒 HTTP 500。具体数值和限制见验收报告。

结论：加载等待主要落在主文档接收及网页启动链路；没有足够证据修改 OP 保护调度。
本轮结束于诊断工具交付，不宣称性能优化完成或网页加载提速。

### M2 — 最小优化（待 M1）

只修改已证实增加开销的 OP 代码路径，优先减少重复观察/遍历和无效调度。
不改变保护判定；若主要瓶颈属于官方页面/服务端，明确报告边界，不扩大为网页重写。
新增测试只覆盖本次变化可能损坏的保护、身份、停止/中断或更新语义。

### M3 — 回归与同条件复测（待 M2）

- JS 语法、diff 检查、Release 构建、严格签名校验、隔离真实 CEF 回归。
- 原断言不放宽；已有或新失败分别报告并解释。
- 对相同会话重复 M1 的 3 轮流程，报告每轮与中位数、样本数、环境/内容变化。
- 若优化涉及 observer，要求对应工作量或同步耗时中位数降低至少 20%；
  frame/long-task/CPU 没有足够样本时不宣称体验改善或固定倍数。
- 核对原登录会话仍可读、已保存消息正文/指纹未丢失、原 dirty 变更均保留；
  实际 UI 滚动与保护/副本入口验证，恢复用户窗口。
